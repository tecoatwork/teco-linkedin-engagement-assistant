# LinkedIn 评论与回复助手

从客户的 LinkedIn 帖子出发，了解作者和公司背景，生成具体、自然、可直接复制的评论与后续回复。

**本 Skill 只研究和起草。点赞、发布评论以及其他账号互动全部由使用者手动完成。**

这是一组供支持 Skill 的 AI 助手读取的工作指令，不是浏览器插件，也不是自动评论机器人。适用于不同行业，不预设使用者的公司、产品或客户。

## 能做什么

| 工作 | 具体交付 |
| --- | --- |
| 阅读帖子 | 理解正文、实际可见的配图与相关讨论，分清作者、转发者及回复对象 |
| 了解公司 | 轻量核实公司主营业务、服务对象、作者职业角色及与帖子相关的动态 |
| 判断讨论角度 | 找到可补充的经验、应用视角、采购判断或值得回答的问题 |
| 撰写评论 | 默认提供一条推荐评论和一条不同角度的备选评论 |
| 继续对话 | 根据客户的实际回复及上文，拟写下一条自然的回复 |

目标是为讨论增加价值，让作者和相关读者注意到你的专业观点；不保证曝光量、回复率或成交。

## 基本使用流程

1. 提供客户帖子的 URL。
2. 助手读取实际可访问的帖子及相关公司公开资料。
3. 简要说明客户背景、帖子核心意思和评论切入角度。
4. 给出可复制的评论正文，解释备选角度。
5. 你自行选择、调整、点赞和发布。
6. 客户回复后，将回复和必要上文发给助手，继续拟写。

如果帖子受到登录或访问限制，助手会尝试一个合适的替代读取渠道；仍无法读取时，请提供正文或截图。它不会把搜索摘要当作已读完整原帖。公司资料无法核实但帖子完整时，可以仅依据帖子起草，并说明背景缺口。

## 建议提供的信息

**最少输入：** 帖子 URL，或完整的帖子正文／截图。

**可选输入：** 我方公司和产品、你的专业身份、与作者的关系、想表达的观点、评论语言、期望长度、以前的对话。

没有我方背景时，助手不会编造“我们工厂”“我们的客户”或合作经历，也不会为了写一条普通评论而强制要求填写完整公司资料。

```text
$teco-linkedin-engagement-assistant
帖子 URL：粘贴客户帖子链接
我方背景：按需要补充
我的观点：按需要补充
请先简要分析，再给推荐评论和一个备选。
点赞和发布由我手动完成。
```

## 使用示例

### 1. 分析客户的新项目

```text
$teco-linkedin-engagement-assistant
这是客户分享新项目的帖子：粘贴链接
请分析作者和公司的相关背景，找一个与项目有关的专业角度。
用英文写评论，不介绍我方产品。
```

### 2. 回应行业讨论

```text
$teco-linkedin-engagement-assistant
这是客户讨论供应商交期的帖子：粘贴链接
请回应他真正关心的问题。不要编造我的供货经历，
也不要泛泛地说“Great insights”。
```

### 3. 客户回复后的第二轮对话

```text
$teco-linkedin-engagement-assistant
原帖：粘贴正文
我之前的评论：粘贴评论
客户刚刚回复：粘贴回复
请沿用之前的语气，直接回应客户，不急于推销。
```

### 4. 只要可复制正文

```text
$teco-linkedin-engagement-assistant
下面是完整帖子：粘贴正文
只给一条英文评论，不需要分析说明。
```

## 输出格式与语言

默认包含三个部分：

- **简短分析：** 3–5 个要点，说明相关背景、帖子意图和切入角度，附实际使用的关键来源。
- **推荐评论：** 可直接复制的正文，与分析分开。
- **备选评论：** 不同角度的简短版本；没有必要时省略。

评论语言跟随原帖或明确要求；分析说明跟随用户语言。默认约 30–80 个英文词，简单祝贺更短，技术讨论可适当展开。这个长度是编辑建议，不是 LinkedIn 算法规则。

不强制每条评论都提问、加标签或带链接。用户要求“只给回复”时省略分析；缺少关键原帖时仍会说明问题，不输出假定制内容。

## 客户分析能力如何复用

可选配合 [teco-target-customer-analyse](https://github.com/tecoatwork/teco-target-customer-analyse) 使用。

已安装时，助手读取其相关指令，限定为与帖子有关的主体、业务和职业角色核实。本任务不默认开展完整信用调查、风险评级、人格分析或开发信制作。

未安装时，按本 Skill 内置的基础核实流程工作，**不会自动安装依赖**。因此该 Skill 可以独立用于评论起草；能否进行公开信息核查取决于宿主提供的读取和联网工具。

## 安装

### 通过 Codex 的 skill-installer

将以下文字发给 Codex：

```text
请使用 skill-installer 安装此仓库根目录中的
teco-linkedin-engagement-assistant Skill：
https://github.com/tecoatwork/teco-linkedin-engagement-assistant
```

仓库根目录就是 Skill 目录，应定位根目录的 `SKILL.md`，而不是寻找同名嵌套目录。

### 手动安装

下载整个仓库，将文件夹命名为 `teco-linkedin-engagement-assistant`，放入宿主配置的技能目录。Codex 常用目录为 `~/.codex/skills/`；自定义环境以实际配置为准。

保持以下结构，尤其不要把 `openai.yaml` 移到根目录：

```text
teco-linkedin-engagement-assistant/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── README.md
├── COPYRIGHT
├── LICENSE
└── .gitignore
```

重新打开会话；如果尚未发现技能，重启客户端并核对安装目录。

## 工具与权限

- 需要能读取 `SKILL.md` 的 AI 助手。
- URL 分析需要实际可用的网页读取或浏览器能力；读取 LinkedIn 的可见范围取决于当前访问条件。
- 没有联网能力时，可分析用户提供的材料，但不能声称已核实最新公司状况。
- 无必需的 API Key、Python 依赖、浏览器自动点赞脚本或私人知识库。
- 本 Skill 不执行点赞、评论发布、私信、关注、添加好友或排期。

## 事实与隐私边界

不虚构公司数据、使用经验、客户关系或产品表现；不因网站精美、员工数或发帖频率而推断财务状况。无法确认的公司身份与任职信息应保持未知。

研究得到的公开信息也不应全部写入评论。只引用与讨论直接相关、适合公开呈现的事实，不披露私人信息，不以个人敏感属性或弱点设计话术。

默认不保存客户档案，不将客户帖子、聊天记录或研究材料写回技能包。技能作者的版权信息不代表对用户提供的客户内容主张所有权。

## 验证状态

创建此通用包时检查了文件结构、YAML、调用名称、版权、私人路径和两版核心文件一致性。标准 Python 验证器所需的 PyYAML 在创建环境中不可用，因此采用可用 YAML 解析器进行替代检查。

不同模型和网页工具可能影响读取范围及评论质量。建议先用一条熟悉的帖子检查事实、语气和评论对象，再逐步调整偏好。
